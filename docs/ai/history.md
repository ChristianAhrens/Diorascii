# How Diorascii came to be

Source: the Claude Code sessions of 2026-11-07 and 2026-11-08 (about 36 hours of work, roughly 40
commits on `main`/`develop`). Times are local (CET).

## Starting point

The owner had an unmodified fork of the Perl `asciiquarium` (one 1,492-line script on
`libcurses-perl` and `Term::Animation`; art inline as `q{}` strings; 8 colors; no resize handling,
no Windows). The first request (2026-11-07 08:55) was a major refactoring: C++, simple CMake, build
scripts for macOS/Windows/Linux, easy deployment (single binary or concise installer, no manual
library gathering), extensible rendered items, same-or-better look, and an outlook to other scenes
(moon, forest with river, mountains, desert) and a rebrand.

## Decisions, in the order they were made

| # | Decision | Why |
|---|---|---|
| 1 | **Own VT/ANSI renderer, no curses** (cell grid, diff against the previous frame, truecolor with 256/16 fallback). Offered as option A of four (curses+PDCurses, FTXUI, notcurses). | The owner liked curses only for assumed performance; zero dependencies and identical builds everywhere mattered more. Curses stays possible later behind the same cell-grid interface. |
| 2 | **No `--classic` mode**; the original look need not be preserved. | Owner: entirely new scenes are the point. |
| 3 | **Data-driven engine**: sprites (`*.sprite`) and scenes (`*.scene`) are text files, embedded at build time, overridable with `--assets DIR`. Custom dependency-free text formats instead of TOML/JSON. Behaviors are C++ functions named in the sprite files. No ECS library, no scripting yet. | Extensibility without recompiling; keep the terminal build at zero dependencies. A scripting hook was discussed and deferred. |
| 4 | **Headless, deterministic core + abstract `Action` input**, frontends on top. | The owner raised tvOS (Siri Remote) and an ASCII menu. The core must be reusable by a custom frontend on platforms without a terminal (originally thought of as SDL3, see decision 13). |
| 5 | **Roadmap**: v1 aquarium, v2 more scenes, v3 tvOS (signed, App Store/TestFlight); originally with an SDL3 windowed frontend, replaced by decision 13. Terminal build is and stays the primary target. | Owner has a developer membership and TestFlight apps; no app is published yet. |
| 6 | **MIT license and 100% original art** ("option 3"). | GPL conflicts with App Store distribution (LGPL is awkward on iOS/tvOS). The art in asciiquarium is largely Joan Stark's with unclear licensing. Owner: "this project is not worth the hassle of starting legal debates with 3rd parties." Alternatives offered and declined: ask the authors to relicense; split GPL art pack from MIT engine. |
| 7 | **Fresh start for provenance**: new tree on an orphan branch, later a brand-new GitHub repo `ChristianAhrens/Diorascii`; the `rewrite` branch became `main`. | Keep GPL material out of the new history. |
| 8 | **Name**: the working title `termarium` / namespace `tmr` was replaced by **Diorascii** / namespace `dio` (binary `diorascii`, options `DIORASCII_*`). The commits were redone under the new name. | Owner's choice. (`tm` was rejected earlier because it collides with C's `struct tm`.) |
| 9 | **Python port (asciiquarium-python, GPL-3) used for ideas only**: feeding, an info overlay, headless tests, a single version source. Its update check was skipped. | Ideas are not copyrightable; text is, so none of its code or its extra fish designs was copied. |
| 10 | **Ambient sound is synthesized**, not recorded: a pure generator in `core`, played through vendored miniaudio, off by default. | A terminal cannot carry audio, but the app can open the device itself. Generated sound fits generated art and keeps the binary small. The owner had considered making audio tvOS-only; the answer was that this is unnecessary. |
| 11 | **Work moves to `develop` after v1.0.0**; `main` receives release merges only. | Owner, 2026-11-07 18:01. |
| 12 | **`CHANGELOG.md` (Keep a Changelog, as in the owner's Umsci project) is the single source** of version and GitHub release text. | Owner, 2026-11-08 00:49. |
| 13 | **tvOS via a native Apple shell, built by CMake; no SDL3, no desktop window** (2026-11-08). Shell in Objective-C++, Xcode project generated by CMake. | Owner: Diorascii is a terminal app and Win/Linux/macOS all have terminals; only tvOS (and perhaps iOS) need a custom layer, so a cross-platform window library has no job. |

## What was not done, on purpose

- No classic mode, no curses backend, no scripting layer, no ECS.
- No relicensing requests to the original authors.
- No update check (from the Python port).
- No recorded audio.
